## Priority 3 - Architecture / Code Size

- [x] **Overhaul multiplayer entity replication**
  - Completed 2026-06-04: heavy shared-state flooding was replaced with a more explicit replicated-entity model for time-sensitive entities.
  - Mobs:
    - moved off the old nearby-mob snapshot bucket into dedicated `mob_sync` packets with `reset`, `spawns`, `updates`, and `despawns`
    - now publish server-authored `vel` and timestamps for client-side smoothing
    - now send on a faster dedicated cadence instead of waiting on the slower general `game_state` rhythm
  - Remote players:
    - UDP position velocity is now normalized to real units-per-second instead of raw packet delta
    - client interpolation now uses the same timestamp-offset buffering model as mobs
    - interpolation delay is now adaptive by combat relevance/distance, so close PvP targets render more responsively than distant players
  - Result:
    - world/building/time/weather/player-loadout sync is stable with multiple players online
    - mobs now render smoothly without the old `smooth -> freeze -> smooth` cadence
    - remote players now stay smooth in general movement while feeling sharper in PvP range

- [x] **Split `client/input/controls.py` by subsystem**
  - Completed 2026-06-03: extracted chat/key-capture, shop handling, inventory/chest drag-drop, and world placement/smart-action routing into `controls_chat.py`, `controls_shop.py`, `controls_inventory.py`, and `controls_building.py`.

## Priority 6 - Server / World Performance

- [ ] **Chunk save/load benchmark and optimization pass**
  - Current status: chunk-based saving/loading exists; `server/world/io.py` uses atomic stdlib JSON writes, while `server/world/dyn_chunk_gen.py` has an `orjson` fast path for V3 chunk load/save.
  - Target: benchmark startup, chunk generation, load, save, and autosave on large worlds; decide whether to consolidate chunk I/O on the faster V3 path or keep separate implementations.

- [ ] **Server chunk cache LRU**
  - Current status: client cache eviction exists; server `world_data` may still grow as players explore.
  - Target: server-side max chunk cache with safe reload from disk.

- [ ] **Spatial index for mob separation**
  - Current status: `server/mobs/mob_manager.py` compares every live mob against every other live mob during separation, which is O(mobs^2) per tick.
  - Target: bucket mobs by tile/coarse cell and only compare mobs in the same or neighboring cells.
  - Benefit: keeps mob AI stable as JSON spawn caps increase.

- [ ] **Spatial indexes for mobs, world items, and placed objects**
  - Current status: `server/game_state/game_sync.py` scans all world items and all mobs per player when building nearby state; placed object queries also scan all placed objects.
  - Target: maintain chunk/cell buckets for nearby queries used by game-state sync, pickups, interaction, and rendering payloads.
  - Benefit: reduce repeated O(players * entities) scans to small local lookups.

- [x] **Avoid building already-sent world chunk payloads**
  - Completed 2026-06-05: `server/game_state/sync.py` now computes visible chunk keys first, subtracts the player’s already-sent chunk set, and only materializes tile payloads for unsent chunks.
  - `server/world/visible.py` now exposes chunk-key discovery separately from chunk payload construction so the sync path can stay cheap when a player is standing still.
  - Follow-up bug fixes from the same work:
    - long-distance teleports now rebuild client terrain state correctly
    - remote observers now receive a fresh teleported player transform immediately instead of waiting for a later UDP movement packet

- [ ] **Non-blocking chunk generation CPU sampling**
  - Current status: `server/world/dyn_chunk_gen.py` calls `psutil.cpu_percent(interval=0.05)` inside chunk processing, which can block the game loop for about 50 ms.
  - Target: use `interval=None`, sample less often, or move chunk generation/CPU monitoring to a worker path.

- [ ] **Delta sync for planted nodes**
  - Current status: `server/game_state/game_sync.py` includes the full planted node snapshot in every game-state payload.
  - Target: send initial planted-node snapshot once, then send adds/removes/updates as deltas.

- [ ] **Connection keepalive cleanup**
  - Current status: UDP movement updates `last_seen`; cleanup handles disconnects.
  - Target: periodic timeout cleanup for players with stale `last_seen`, even if sockets remain half-open.

- [ ] **NumPy/Numba fallback strategy**
  - Current status: `server/world/dyn_chunk_gen.py` imports NumPy and Numba at module import.
  - Target: graceful startup message or fallback path if acceleration dependencies are missing.

- [ ] **Dropped world item persistence**
  - Current status: players, placed objects, resource-node depletion/respawn, planted nodes, and chunks persist; dropped `world_items` appear to be runtime-only.
  - Target: persist dropped items separately from chunks so server restarts do not wipe loose drops or dungeon/chest rewards left on the ground.

- [ ] **Serialization/compression benchmark**
  - Current status: the old performance roadmap says zlib compression was done, but current hot paths primarily use `orjson` with length-prefixed messages.
  - Target: benchmark raw `orjson`, zlib-compressed JSON, and optional MessagePack for world chunks/game-state payloads; only adopt compression if it improves real network or CPU behavior.

- [ ] **Human-readable persistence files**
  - Current status: player saves and ops use `indent=2`; placed objects/resource-node persistence/chunk saves mostly do not.
  - Target: decide which files should remain compact for performance and which should use readable formatting.
